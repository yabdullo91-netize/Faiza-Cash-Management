## Что реализовано

Отдельные ASP.NET Core API и React/Vite клиент на JavaScript; PostgreSQL и EF Core миграции. Приход, расход, черновики, проведение, связанное сторно с причиной, точные суммы, автоматическая нумерация, блокировка кассы при проведении. Роли admin/accountant/cashier и индивидуальный доступ к кассам. JWT в памяти браузера, HttpOnly refresh cookie, ротация и отзыв, CSRF заголовок и проверка Origin, ограничение входа. Журнал, поиск, фильтры, сортировка, пагинация, справочники, график движения, CSV и настоящий серверный PDF, аудит, настройки, светлая/тёмная темы.

## Уже настроенное локальное окружение

Команды выполняются из папки faiza-cash. Секреты текущего запуска находятся только в игнорируемом файле .runtime/local.json. Поля Seed__AdminLogin и Seed__AdminPassword содержат данные локального администратора. Не публикуйте этот файл. Существующая .env сохранена, но новая версия её не использует. Устаревшая версия в корневой папке src/ удалена; действующий сервер находится в backend/src/.

1. Соберите сервер: `dotnet build backend/FaizaCash.sln`.
2. Запустите API: `node scripts/run-local.mjs` — http://localhost:5080.
3. В другом терминале: `cd frontend`, затем `npm ci` и `npm run dev`.
4. Откройте **http://localhost:5173**. Вход с первоначальным паролем требует его смены.
5. При необходимости явно наполните пустую учебную базу: `node scripts/seed-demo.mjs`. Сначала смените первоначальный пароль в интерфейсе и задайте FAIZA_ADMIN_PASSWORD через окружение, если пароль отличается от локальной конфигурации. Будут созданы 21 проведённая операция и три черновика с вымышленными контрагентами. Повторное наполнение базы с кассами пропускается. Старые демонстрационные записи по тексту назначения автоматически не исправляются. Ранее существовавший режим `--bootstrap` меняет первоначальный пароль и не должен применяться без отдельного поручения на такую подготовку.

Для нового компьютера нужны .NET SDK 10, Node.js >=22.12 и PostgreSQL. Задайте через окружение ConnectionStrings__CashDb, Jwt__Key (>=32 символов), Seed__AdminPassword (>=10 символов, буквы и цифры), ASPNETCORE_ENVIRONMENT=Development, ASPNETCORE_URLS=http://localhost:5080. Выполните `dotnet run --project backend/src/FaizaCash.Api`. Миграции применяются при старте. Базу создайте заранее, пользователь должен владеть её схемой. Первоначальный администратор создаётся только в пустой базе.

## Docker Compose

Скопируйте .env.example в .env.docker, задайте уникальные POSTGRES_PASSWORD, JWT__KEY, SEED__ADMINPASSWORD. Выполните `docker compose --env-file .env.docker up --build`; интерфейс: http://localhost:8080. Compose предназначен для локальной демонстрации, привязан к loopback и использует Development. PostgreSQL имеет отдельный volume postgres-data-v2, старый volume не изменяется. Docker Desktop в этой сессии не был запущен, поэтому контейнерный запуск не проверен.

## Ограничения и эксплуатация

Это учебный продукт, не сертифицированная бухгалтерская система. Валюта одна, по умолчанию TJS; начальный остаток вводится обычной приходной операцией. Сторно сначала создаёт обратный черновик: до проведения остаток не меняется. Денежные JSON значения — строки, расчёт выполняет сервер; графики округляются браузером только для отображения. PDF создаётся QuestPDF с Community license для академического проекта; перед коммерческим использованием проверьте применимую лицензию.

Для production нужны TLS, отдельные настройки reverse proxy/forwarded headers, управление секретами, ограниченная роль БД, проверка резервного восстановления, проверка нагрузки и независимый аудит безопасности. JWT действует до 15 минут; при выходе отзывается refresh, уже выданный access остаётся действителен до истечения. Отключение пользователя и снятие роли проверяются сервером на каждом запросе. Журналы JSON ротируются по дню/10 MiB, хранятся 14 дней; в Compose технические журналы контейнера временные. Кэш справочников — 30 секунд, инвалидируется при изменениях, остатки не кэшируются. Для шрифта интерфейса используется Google Fonts с системным fallback; работа функций от внешнего шрифта не зависит.

Оставшаяся ручная проверка: полный сценарий в браузере, его консоль, адаптивность и живое управление клавиатурой. PDF отрендерены отдельно: русский текст, переносы, повтор заголовков и итоги просмотрены, включая восьмистраничный отчёт. Подробности архитектуры, прав и защиты — docs/. Фактические проверки и ограничения: [docs/interface-review.md](docs/interface-review.md). Клиентские проверки запускаются командой `npm test` из frontend. Восстановление из pg_dump ранее проверено в отдельной тестовой базе.
