# Доработка интерфейса и контроль качества — 12 ноября 2026

## Что было подтверждено

Стек сохранён: JavaScript/React/Vite → ASP.NET Core API → Application/Domain → EF Core/PostgreSQL. Существующие незакоммиченные изменения не сбрасывались. Файл технического задания не переписывался. Финансовые операции и роли рабочей базы не изменялись. Изменения схемы не потребовались: применяются прежние миграции.

Причина риска падения «Пользователей» подтверждена кодом: один `data` использовался всеми разделами, а `r.roles.join()` выполнялся сразу при смене страницы, до сброса состояния в эффекте. В этот момент `rows` могли содержать операции, у которых нет `roles`. Запоздалые ответы запросов дополнительно могли заменить данные нового раздела. Проверить исходное падение кликами в браузере не удалось; сценарий несовместимых данных воспроизведён регрессионными проверками.

Также подтверждены мелкий текст, технические названия аудита, отсутствие адресов разделов, несоответствие экспорта фильтрам, прокрутка формы вместе с фоном, выбор первой подходящей категории в генераторе демоданных и потеря точности больших чисел в графических подсказках.

## Реализованные изменения

- Данные страницы имеют ключ раздела, фильтров, пользователя и версии загрузки. Предыдущие данные не попадают в новый раздел даже до выполнения эффектов. Запросы отменяются через AbortController; поздние ответы не обновляют закрытый раздел.
- Введён явный UserDto с массивом ролей. Клиент проверяет контракт списка и сеанса. Отсутствующий `roles` вызывает понятную ошибку загрузки, а пустой массив отображается как «Роль не назначена». ErrorBoundary сохраняет меню и предлагает повторить загрузку или перейти в обзор.
- Добавлены адреса `#/overview`, `#/operations`, `#/users` и остальных разделов. В URL сохраняются касса, даты, фильтры, сортировка и страница. Переходы разделов поддерживают историю браузера; изменение фильтров обновляет текущую запись истории, не создавая её на каждый символ поиска.
- Меню сгруппировано: работа с деньгами, справочники, администрирование. Убрана стрелка внешней ссылки. Действия и карточки учитывают роли и авторство черновика; серверные проверки сохранены.
- Типографика увеличена: основные элементы 14–16 px, различимые вспомогательные подписи. Цвета, поля, кнопки, состояния и размеры сведены в токены refinements.css. Контраст основных текстовых токенов обеих тем проверен расчётом: не менее 4,5:1. Это не является полной визуальной сертификацией WCAG.
- Диалоги имеют отдельную прокрутку тела, неподвижные заголовок и кнопки. Фон блокируется; Escape, цикл Tab и возврат фокуса реализованы в общем компоненте. Поля суммы принимают запятую и точку, проверяются без float; ошибки клиентской валидации показаны у полей. Черновик открывается для проверки после сохранения.
- Финансовые показатели не показывают ложные нули при загрузке. Порядок карточек: начальный остаток → приход → расход → конечный остаток. Есть «Сегодня», последние семь дней («Неделя»), текущий календарный месяц и произвольный включительный период.
- Вместо сглаженных линий используются дневные столбцы. Приход и расход по категориям разделены. Точные строки денежных значений используются для сумм и подсказок; приблизительные JavaScript-числа применяются только для масштаба графики.
- Журнал имеет поиск, кассу, даты, направление, статус, категорию, контрагента, сброс, сортировку и серверную пагинацию. CSV/PDF включают весь найденный набор с фильтрами, а не одну страницу. Экспорт журнала может включать черновики; это указано в интерфейсе.
- Отчёты содержат отдельную учебную кассовую книгу: дата, номер, основание, контрагент, приход, расход и последовательный остаток. Порядок стабилен по дате, очереди проведения и id. Остаток корректен между страницами. Книга включает все проведённые записи выбранной кассы за период; дополнительные фильтры применяются в журнале, чтобы не создавать ложный остаток.
- CSV экранирует поля, использует UTF-8 BOM и `;`, защищает формулоподобные строки. Кассовая книга CSV содержит начальный остаток, остатки строк и итоги. PDF повторяет заголовки, переносит длинный текст и использует встроенные шрифты. Документы помечены как учебные.
- Аудит показывает имена сотрудников, русские действия и объекты, понятное описание документа. Есть фильтры по датам, пользователю, действию, объекту и служебным событиям. Технические поля раскрываются отдельно, JSON разбирается стандартным JSON.parse. Новые изменения безопасных полей и ролей сохраняются в формате «было → стало». Пароли, токены и хеши в этот снимок не включаются. Исторические события не удалены.
- Справочники проверяют повторные имена с учётом регистра и пробелов. Параллельное создание одинакового имени сериализуется транзакционной блокировкой. Использованные записи архивируются; старые ссылки и названия документов сохраняются. Контрагента в черновике можно явно очистить, не меняя семантику старых PATCH-запросов с пропущенным полем.
- Генератор демоданных сопоставляет категорию и контрагента по смыслу, создаёт 21 проведённый документ и три черновика. Новое наполнение допустимо только в пустой явно выбранной учебной базе. Старые демонстрационные и рабочие документы автоматически не исправлялись.

## Что осталось непроверенным

Автоматизация браузера остановлена инструментом Computer Use: он не смог надёжно определить URL окна Chrome; прямой browser access host также недоступен. Поэтому нет контрольных снимков веб-страниц и не подтверждены отсутствие ошибок браузерной консоли, живые переходы «Назад/Вперёд», фокус/прокрутка в реальном браузере и внешний вид при 100% масштабе на 1440, 1280, 1024, 768 и 390 px. Для этих ширин добавлены CSS-правила, но кодовые и SSR-тесты не заменяют визуальную проверку. Нельзя считать все визуальные критерии задания закрытыми.

Контрольные изображения PDF не являются снимками веб-интерфейса. Нагрузочное тестирование и независимый пентест не выполнялись. Docker Desktop не запускался.

Ручная проверка: открыть каждый раздел, быстро переключить «Операции → Пользователи» при медленной сети, обновить URL раздела, проверить историю браузера, ввод фильтров без потери фокуса, открыть длинную форму и пройти её клавишей Tab, проверить отсутствие фоновой/горизонтальной прокрутки на телефоне. Финансовые действия выполнять только в отдельной тестовой или явно подготовленной учебной базе.

## Запуск и демонстрация

Из корня `faiza-cash`: `dotnet build backend/FaizaCash.sln`, затем `node scripts/run-local.mjs`. В другом терминале из `frontend`: `npm ci`, `npm run dev`. Адрес: http://localhost:5173. Данные локального входа находятся в игнорируемом `.runtime/local.json`; не показывайте его на защите. Новых миграций нет, старые применяются при старте.

Проверки: `node tests/run-all.mjs`; отдельно в `frontend` — `npm test` и `npm run build`. Тестовая база имеет суффикс `_test`, рабочая база не очищается. Обновлённый генератор не запускается автоматически.

Короткая защита: вход → выбранная касса и период → приходный черновик → карточка и проведение → расход → проверка остатка → поиск/фильтры → кассовая книга и PDF/CSV → аудит с именами → показ ограничений кассира. Подробный сценарий — [defense.md](defense.md).

Простое объяснение: интерфейс собирает данные и отправляет HTTP-запрос; API проверяет вход и права; бизнес-правила проверяют сумму, состояние документа и доступный остаток; EF Core сохраняет документ и аудит одной транзакцией PostgreSQL. Черновик хранится, но не меняет остаток. Исправление проведённой записи выполняется связанным сторно.
