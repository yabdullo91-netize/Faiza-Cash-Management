# Фактически выполненные проверки

Дата: 12 ноября 2026 года, часовой пояс пользователя Asia/Dushanbe.

Актуальный итог после проверки интерфейса: **19 unit-тестов, 21 integration-проверка, 12 security-проверок и 12 клиентских проверок пройдены**. Подробности новых исправлений и оставшихся ручных проверок — [interface-review.md](interface-review.md). PDF отдельно отрендерены и просмотрены, включая русский текст, таблицы и первую/последнюю страницы восьмистраничного отчёта; [контрольные изображения](qa/README.md). Новых миграций нет; рабочие записи не исправлялись и не пересоздавались. Ниже сохранена история предыдущих проверок.

Обновление тестирования: добавлен отдельный xUnit-проект с **19 пройденными unit-тестами**, отдельно запущены **12 integration-проверок** и **12 security-проверок** на настоящем PostgreSQL. В каждом PostgreSQL-наборе одна проверка относится к общей подготовке администратора. Команда общего запуска: `node tests/run-all.mjs`; устройство наборов — [testing.md](testing.md). Актуальные раздельные результаты: `.runtime/unit-results/unit-tests.trx`, `.runtime/integration-test-results.json`, `.runtime/security-test-results.json`.

Security-набор нашёл и помог исправить ошибку middleware: пустой JSON-запрос на проведение мог возвращать 500. Проверка доступа по id теперь выполняется до чтения тела; тело разбирается только для создания/изменения документа, неверный JSON возвращает 400. Есть регрессионная проверка разрешённого проведения собственного черновика кассиром и запрета проведения чужого документа.

- .NET 10: решение из четырёх проектов собрано без ошибок и предупреждений.
- React/Vite: production-сборка выполнена. JavaScript, TypeScript не используется. Зависимости зафиксированы в package-lock.json и NuGet packages.lock.json.
- PostgreSQL 18.3: отдельная роль и две новые базы, миграции InitialLedger и ImmutableLedger применены. Существующие базы пользователя не изменялись.
- Базовый API-прогон до разделения наборов: 15 пройденных проверок на настоящем PostgreSQL. Эти сценарии сохранены в раздельных наборах: обязательная смена первого пароля; точная сумма и начальная операция; отрицательные/нулевые/субкопеечные суммы; повтор создания; параллельные расходы; повтор проведения; защита проведённого документа; связанное сторно; отчёт и CSV; серверный PDF; роли и доступ к кассам; аудит; откат при искусственном сбое аудита; CSRF; ротация, reuse и отзыв refresh.
- Два JavaScript теста HTTP-клиента: параллельные 401 используют один refresh; серверная ошибка 403 сохраняет пояснение и не вызывает повторных запросов.
- pg_dump/pg_restore: выполнен полный цикл custom-format в отдельной тестовой базе. Совпали количество операций, проведённых операций, событий аудита и денежная сумма. Рабочая база для этого не очищалась.
- Явное учебное наполнение: 21 проведённая операция, справочники и вымышленные контрагенты. Начальный остаток — приходная операция.
- API http://localhost:5080/health и клиент http://localhost:5173 вернули HTTP 200.
- docker compose config --quiet: конфигурация синтаксически принята. Контейнеры не запускались: Docker Desktop не работал.

Подробный машинный результат тестов находится в локальном игнорируемом .runtime/test-results.json, результат восстановления — .runtime/backup-verification.json. Они не содержат паролей. PDF-артефакты тестов сохранены в .runtime/.

Не выполнено: весь сценарий через браузер, его консоль и проверка мобильного экрана. Прямой browser access host недоступен; последняя попытка Computer Use остановлена инструментом из-за невозможности надёжно определить URL Chrome. HTTP 200, сборка и SSR-проверки не заменяют живую проверку страниц. PDF отрендерены отдельно и просмотрены. Не выполнены контейнерная сборка, нагрузочное тестирование и независимый аудит безопасности. Готовность к промышленной эксплуатации не заявляется.
