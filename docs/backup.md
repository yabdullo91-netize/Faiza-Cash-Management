# Резервное копирование и восстановление

Резервная копия PostgreSQL содержит персональные и финансовые данные; храните её вне репозитория с ограниченным доступом. Перед обновлением снимите копию. Используйте pg_dump той же или более новой основной версии, чем сервер.

Локальный пример (пароль задаётся через интерактивный запрос, не включайте его в команду):

```powershell
pg_dump -h 127.0.0.1 -U YOUR_APP_ROLE -d YOUR_DATABASE -Fc -f faiza-backup.dump
createdb -h 127.0.0.1 -U YOUR_ADMIN_ROLE faiza_restore_check
pg_restore -h 127.0.0.1 -U YOUR_ADMIN_ROLE -d faiza_restore_check --no-owner faiza-backup.dump
```

Восстанавливайте сначала в новую пустую базу. Не применяйте --clean к рабочей базе. Сверьте число операций, суммы по кассам, журнал аудита и миграции, затем проверьте вход и отчёт. Только после проверки планируйте переключение строки подключения. Для Compose используйте docker compose exec -T db pg_dump, бинарный файл сохраняйте через корректную бинарную переадресацию (Windows PowerShell 5 может повредить stdout; безопаснее pg_dump -f внутри контейнера и docker compose cp).

В этой сессии проверено применение миграций и полный цикл pg_dump/pg_restore в отдельной тестовой базе: количество документов, проведённых записей, событий аудита и сумма совпали. Скрипт проверки: `node scripts/verify-backup.mjs` (запускайте после интеграционных тестов, не параллельно с ними). Он сохраняет dump и очищает/восстанавливает только отдельную базу с суффиксом _test; рабочую базу не изменяет. Это не заменяет проверку восстановления ваших будущих рабочих данных.
